# 차곡 기획 초안

작성일 2026년 10월 27일 · 버전 0.8

프로젝트명(코드네임)은 차곡(chagok)이다. '차곡차곡 쌓인다'는 뜻으로, 하루를 쉬어도 쌓인 것은 사라지지 않는다는 이 서비스의 핵심 원칙을 담았다. 출시할 서비스명은 따로 정한다. (14장)

장기 목표를 오늘 할 수 있는 행동으로 나누고, 할 일을 완료할 때마다 나만의 마을과 집이 만들어지는 모바일 중심 서비스다. 목표 하나가 건물 하나가 되고, 실행으로 모은 크레딧으로 집을 꾸미고 넓혀간다. 목표를 할 일로 나누는 과정은 AI가 돕는다.

이 문서에는 논의로 정한 내용과 검토용 제안이 섞여 있다. 정한 내용은 '확정', 수치는 '러프안', 제안은 '제안'으로 표시한다. 러프안 수치는 직접 사용하면서 조정한다.

### v0.7 대비 주요 변경

- 와이어프레임과 화면 구현에 Impeccable을 쓰기로 확정했다. 프로젝트 초기 세팅 후 설치한다. (15.8)
- 슬롯 종류와 업적 목록은 미정으로 두고, 와이어프레임에서는 임시 값으로 진행한다. (14장)
- AI 초안 개수 상수를 최소값과 최대값으로 나눴다. (용어집 8장)

### v0.6 대비 주요 변경 (v0.7)

- 프로젝트명(코드네임)을 차곡(chagok)으로 정했다. 저장소 이름은 `chagok-web`, `chagok-api`로 한다. (15.1, 15.2)
- 서비스명은 상표와 동명 앱을 확인한 뒤 출시 전에 정한다. (14장)

### v0.5 대비 주요 변경 (v0.6)

- 오늘 할 일이 없을 때 모달 대신 빈 화면 카드를 보여주기로 했다. (9.5, 9.6)
- 빠른 추가 기능을 추가했다. 키워드와 수량만 골라 할 일을 만들며, DB 템플릿으로 동작하고 AI를 호출하지 않는다. (9.6)
- AI로 만든 할 일은 날짜 없이 생성되고, 빈 화면 카드의 '목표에서 가져오기'로 오늘에 넣는다.
- 와이어프레임 준비 문서(PRODUCT.md, 용어집, 화면 명세서, CLAUDE.md)를 별도로 작성했다. 화면 단위의 세부 동작은 화면 명세서를 따른다.

## 1 기획 목적

### 1.1 만드는 이유 (확정)

- 본인이 실제로 쓰기 위해 만든다. 첫 사용자는 본인이다.
- 백엔드 포트폴리오로 활용한다.
- 시장에서 유일한 서비스를 목표로 하지 않는다.
- 최종적으로 앱스토어 배포를 목표로 한다. 첫 버전은 웹으로 만든다.

### 1.2 해결할 문제 (확정)

| 이탈 이유 | 설계 원칙 |
| --- | --- |
| 매일 해야 한다는 부담 | 하루를 빠져도 잃는 것이 없다. 연속 기록이 끊겨도 처벌하지 않는다. |
| 목표를 세우고 체크하는 과정이 귀찮음 | AI가 할 일 초안을 만들고 사용자는 고르기만 한다. 매일 입력하는 선택 항목을 두지 않는다. |
| 텍스트로만 되어 있어 재미없음 | 실행 결과를 마을, 건물, 집의 변화로 보여준다. |

### 1.3 초기 가설

목표를 할 일로 나누는 부담이 적고, 완료할 때마다 눈에 보이는 결과가 쌓이며, 하루를 쉬어도 쌓인 것이 사라지지 않으면 실행을 오래 이어갈 수 있다.

## 3 AI 목표 분해 (확정, 첫 버전)

### 3.1 흐름

1. 사용자가 목표 제목을 입력한다. 기한과 현재 상황은 선택 입력이다.
2. AI가 목표 유형(건물 종류)과 할 일 초안 5~10개를 제안한다.
3. 사용자는 할 일을 체크해서 고르고, 필요하면 제목을 고친다. 선택 방식은 3.2를 따른다.
4. 고른 할 일만 목표에 연결되어 생성된다.

### 3.2 초안 선택 방식 (확정)

- 초안은 모두 해제된 상태로 보여준다. 필요 없는 할 일이 대충 넘어가 쌓이는 것을 막기 위해서다.
- 목록 위나 아래에 선택 전환 버튼을 하나 둔다.

| 선택 상태 | 버튼 문구 | 버튼을 누르면 |
| --- | --- | --- |
| 하나도 선택 안 함 | 모두 선택 | 전부 선택 |
| 일부만 선택 | 모두 선택 | 나머지까지 전부 선택 |
| 전부 선택 | 모두 해제 | 전부 해제 |

- 완료 버튼에는 선택한 개수를 표시한다. 예: '3개 추가하기'
- 선택이 0개이면 완료 버튼을 비활성화한다.

### 3.3 규칙

- AI 제안은 사용자가 확인하기 전에는 저장하지 않는다.
- 할 일 초안은 한 번에 실행할 수 있는 크기로 만든다. 예를 들어 '포트폴리오 만들기' 대신 '포트폴리오에 넣을 프로젝트 3개 고르기'다.
- AI 호출이 실패하거나 응답이 늦으면 직접 입력으로 넘어갈 수 있다. AI 없이도 목표와 할 일을 만들 수 있어야 한다.
- 사용자별 하루 호출 횟수에 상한을 둔다. 러프안은 하루 10회다.
- AI가 만든 할 일도 일반 할 일과 같은 규칙으로 크레딧을 받는다. 할 일을 생성하는 것만으로는 크레딧을 주지 않는다.

### 3.4 후속

- 기존 할 일 하나를 AI로 더 작게 쪼개기
- 진행 상황을 보고 다음 할 일 추천

## 4 게임 구조

### 4.1 마을과 건물 (확정)

- 사용자마다 마을 하나를 가진다. 마을 중심에는 사용자의 집이 있다.
- 목표 하나를 만들면 마을에 건물 하나가 생긴다.
- 목표에 연결된 할 일을 완료하면 그 건물의 공사가 자동으로 진행된다.
- 목표 건물의 공사는 크레딧으로 진행하지 않는다.

목표 유형별 건물 (제안)

| 목표 유형 | 건물 |
| --- | --- |
| 취업, 이직 | 오피스 |
| 공부, 자격증 | 학교 |
| 저축, 재테크 | 은행 |
| 운동, 건강 | 체육관 |
| 개인 프로젝트 | 작업실 |

학교나 회사의 등급은 표현하지 않는다. 비교 대상은 과거의 나다. 실제 회사나 학교의 이름과 로고는 사용하지 않는다.

### 4.2 건물 단계 (러프안)

| 단계 | 조건 |
| --- | --- |
| 터 | 목표 생성 시 |
| 골조 | 연결된 할 일 5개 완료 |
| 완성 | 사용자가 목표를 완료 처리 |

- 연결된 할 일을 모두 끝내도 건물은 자동으로 완성되지 않는다. 목표 완료는 사용자가 결정한다.
- 목표를 보관하면 공사만 멈춘다. 건물은 부서지지 않는다.
- 목표 없이 만든 할 일은 건물 공사에 반영되지 않는다. 크레딧 지급 대상은 된다.
- 장기 목표는 골조 단계에 오래 머물 수 있다. 사용해보고 정체돼 보이면 골조와 완성 사이에 중간 단계를 추가한다.

### 4.3 크레딧 (러프안)

- 할 일 개수는 제한하지 않는다.
- 자기 신고 방식이라 부정 체크를 완벽히 막을 수는 없다. 랭킹과 비교 기능이 없으므로, 목표는 크레딧 균형을 유지하는 것으로 한다.

| 지급 | 크레딧 | 상한 |
| --- | --- | --- |
| 핵심 할 일 완료 | 1개당 20 | 핵심 할 일 최대 3개 → 하루 60 |
| 일일 보너스 (일반 할 일 5개 완료) | 20 | 하루 1회 |
| 업적 달성 | 업적별 소량 | 업적당 1회 |

- 하루 최대는 업적을 빼고 80이다.
- 하루 평균 50, 주 5일 실행 기준으로 주간 약 250을 예상한다.
- 일반 할 일은 하나씩 크레딧을 주지 않는다.
- 크레딧은 가구 구매와 집 업그레이드에 사용한다.

### 4.4 집과 가구 (러프안)

| 업그레이드 | 필요 가구 (누적 설치) | 가구 가격대 | 업그레이드 비용 | 예상 기간 |
| --- | --- | --- | --- | --- |
| 원룸 → 투룸 | 3개 | 개당 약 80 | 300 | 약 2주 |
| 투룸 → 아파트 | 7개 | 개당 약 130 | 700 | 약 5주 |
| 아파트 → 주택 | 12개 | 개당 약 200 | 1500 | 약 10주 |

- 주택까지 약 4개월이 걸리고, 그 사이 2~5일마다 가구를 하나씩 살 수 있다.
- 이사할 때 가구는 그대로 가져가고, 가져간 가구도 설치 수에 포함된다.
- 집이 커지면 가구 슬롯이 늘어난다. (예: 원룸 4, 투룸 8, 아파트 13, 주택 18)
- 가구는 고정 슬롯 방식으로 설치한다. 정해진 자리마다 가구를 골라 넣으며, 드래그와 회전은 없다.
- 마을에서 집을 누르면 집 내부 화면으로 들어간다.

### 4.5 일일 보너스 (확정)

- 일반 할 일을 하루 5개 완료하면 하루 1회 지급한다.
- 받지 못한 날에도 손해는 없다.
- 영구 기록인 업적과 구분하기 위해 이름을 따로 둔다.

### 4.6 업적 (확정)

- 실행 기준은 접속이 아니라 '실행한 날'이다. 실행한 날은 할 일을 하나 이상 완료한 날이다.
- 누적 업적을 중심으로 둔다. 예: 총 30일 실행, 일반 할 일 총 100개 완료
- 연속 업적은 한 번 얻으면 영구히 남는다. 현재 연속 일수는 화면에 크게 표시하지 않는다.
- 복귀 업적을 둔다. 예: 일주일 쉬고 다시 실행
- 목표 달성 업적을 둔다.
- 보상은 배지와 소량의 크레딧이며 한 번만 지급한다.

### 4.7 시즌·테마 가구 (초기 계획)

- 시즌과 테마별로 가구를 계속 추가해 크레딧을 쓸 곳이 사라지지 않게 한다.
- 가구 정보는 데이터로 관리한다. 새 가구를 추가할 때 앱을 다시 배포하지 않는다.
- 기간 한정 판매로 압박하지 않는다.
- 첫 버전에는 기본 가구만 넣고 시즌 가구는 후속으로 둔다.

## 5 그래픽 (확정)

3D로 모델을 만들고 아이소메트릭 시점의 2D 이미지로 렌더링해 사용한다.

- 3D 모델에서 렌더링하므로 조명, 비율, 각도가 통일된다.
- 앱에서는 렌더링된 이미지만 쓰므로 모바일에서도 가볍다.
- 실시간 3D는 사용하지 않는다.
- 마을 외관, 건물, 집 내부, 가구를 모두 같은 방식으로 맞춘다.
- 가구는 슬롯마다 정해진 각도로만 렌더링한다.

| --- | --- |
| 목표 건물 | 5~6종 × 3단계 = 15~18장 |
| 집 외관 | 4장 |
| 집 내부 배경 | 4장 |
| 기본 가구 | 약 15~20종 |
| 합계 | 약 40~45장 |

## 6 플랫폼과 이용 원칙 (확정)

- 첫 버전은 모바일 친화적 웹으로 만들고 PWA 설치를 지원한다.
- 1차 검증 기기는 본인의 안드로이드 폰이다. PWA 설치와 웹 푸시를 그대로 사용할 수 있어 검증 단계까지 비용이 들지 않는다.
- 앱스토어 배포 방식은 출시 시점에 정한다. (15.6 참고)
- 할 일은 제목만으로 추가할 수 있다.
- 완료는 탭 한 번 또는 스와이프로 끝난다.
- 매일 입력해야 하는 선택 항목을 두지 않는다.
- 알림 권한은 사용자가 알림을 켤 때 요청한다.
- 설치와 알림을 거부해도 핵심 기능을 사용할 수 있다.

| 기록 | 날짜별 실행 내역, 주간 집계 | 장기 추세 |
| 회고, 컨디션, 미완료 이유 | 제외 | 사용해보고 필요하면 추가 |
| 알림 | 웹 푸시 (안드로이드에서 검증) | 앱 푸시 |

### 7.1 개발 순서 (제안)

1. 목표, 할 일, 오늘 화면, 완료와 재계획
2. AI 목표 분해
3. 크레딧, 일일 보너스, 마을과 목표 건물
4. 집 내부, 가구 구매와 설치, 집 업그레이드
5. 업적, 기록, 알림

## 8 목표와 할 일의 관계

| 구분 | 의미 | 예시 |
| --- | --- | --- |
| 목표 | 이루고 싶은 결과. 건물 하나와 연결 | 백엔드 개발자로 취업하기 |
| 할 일 | 한 번에 실행할 구체적인 행동 | 관심 공고에서 주요 업무 3개 정리하기 |
| 오늘 계획 | 특정 날짜에 수행하기로 정한 할 일 | 지원동기 첫 문단 작성하기 |

- 세부 단계와 이번 주 계획은 후속으로 미룬다.
- 할 일은 목표에 연결하거나 목표 없이 만들 수 있다.
- 목표 달성과 할 일 완료는 구분한다.

## 9 화면 구성과 흐름

### 9.1 화면 지도 (제안)

하단 탭은 '오늘, 마을, 목표, 기록' 4개로 구성한다. 로그인 후 기본 진입 화면은 오늘이다.

| 탭 | 주요 내용 | 이어지는 화면 |
| --- | --- | --- |
| 오늘 | 핵심 할 일 최대 3개, 나머지 할 일, 일일 보너스 진행, 지난 미완료 안내, 할 일 추가 버튼, 할 일이 없을 때 빈 화면 카드 | 할 일 추가 (제목만 입력), 빠른 추가 (키워드와 수량 선택) |
| 마을 | 집과 목표별 건물, 크레딧 잔액 | 집 내부 (가구 슬롯, 가구 상점, 업그레이드 조건과 비용) |
| 목표 | 목표 목록 | AI 분해 (새 목표 만들기) → 목표 상세 (연결된 할 일, 건물 단계) |
| 기록 | 날짜별 실행 내역, 주간 요약 | 업적 (배지 목록) |

### 9.2 첫 진입 (확정)

- 로그인 직후 목표가 0개이면 바로 AI 분해의 목표 입력 화면으로 이동한다.
- '나중에 하기'를 누르면 빈 오늘 화면으로 간다.
- 긴 설문이나 튜토리얼은 두지 않는다.

### 9.3 핵심 시나리오 (확정)

시나리오 1: AI로 목표 만들기

| 순서 | 화면 | 내용 |
| --- | --- | --- |
| 1 | 목표 탭 | 새 목표 버튼 (첫 진입 시에는 자동으로 2번 화면) |
| 2 | 목표 입력 | 제목 필수, 기한 선택 |
| 3 | AI 분해 중 | 건물 종류와 할 일 초안 생성 |
| 4 | 할 일 초안 선택 | 3.2의 선택 방식으로 고르고 수정 |
| 5 | 목표 상세 | 목표와 할 일 생성, 마을에 건물 터 생성 |

AI 실패나 시간 초과 시 3번에서 직접 입력 화면으로 넘어가고, 직접 입력을 마치면 5번으로 간다. 입력한 목표 제목은 유지한다.

시나리오 2: 할 일 완료부터 집 업그레이드까지

| 순서 | 화면 | 내용 |
| --- | --- | --- |
| 1 | 오늘 | 할 일 완료 (탭 한 번) |
| 2 | 오늘 (알림) | 크레딧 지급(핵심 할 일, 일일 보너스)과 건물 공사 진행(목표 연결 할 일)을 짧은 알림으로 표시 |
| 3 | 마을 → 집 내부 | 집을 눌러 입장 |
| 4 | 집 내부 | 빈 슬롯을 골라 가구 구매, 설치 |
| 5 | 집 내부 | 가구 수와 비용 조건을 채우면 업그레이드 |

업그레이드하면 새 슬롯이 열리고 가구 모으기가 다시 시작된다. 크레딧만 집으로 이어지고, 건물 공사는 마을에서만 확인한다.

### 9.4 완료 피드백 규칙 (확정)

- 할 일을 완료해도 화면을 이동시키지 않는다. 오늘 화면에서 짧은 알림만 보여준다. 예: '+20 크레딧 · 오피스 공사 진행'
- 알림에는 실행 취소 버튼을 함께 둔다.
- '마을 보러 가기' 안내는 아래 두 경우에만 보여준다.
  - 오늘 할 일을 모두 완료했을 때
  - 집 업그레이드 조건을 채웠을 때
- 이전 날짜의 미완료 일은 오늘 목록에 자동으로 쌓지 않는다.

### 9.6 빈 화면 카드와 빠른 추가 (확정)

오늘 할 일이 없을 때 직접 입력하는 귀찮음을 줄이기 위한 기능이다. 할 일이 없는 날마다 모달을 띄우면 매번 닫아야 하는 부담이 생기므로, 오늘 화면의 빈 자리에 카드로 보여준다.

빈 화면 카드 구성 (위에서 아래 순서)

| 순서 | 구성 | 조건 |
| --- | --- | --- |
| 1 | 목표에서 가져오기 (날짜 없는 할 일 최대 3개) | 진행 중 목표에 날짜 없는 할 일이 있을 때 |
| 2 | 빠른 추가 칩 (러프안 최대 8개) | 항상 |
| 3 | 직접 입력 | 항상 |
| 4 | AI로 목표 만들기 | 진행 중 목표가 0개일 때 |

AI 분해로 만든 할 일은 날짜 없이 생성되므로, 첫 목표를 만든 뒤에는 1번으로 바로 오늘 할 일을 채울 수 있다.

빠른 추가 동작

1. 칩(예: 독서)을 누른다.
2. 단위와 수량을 고른다. 예: 분 → 20
3. 필요하면 매일 반복을 켠다.
4. 추가하면 '독서 20분'이라는 오늘 할 일이 생성된다.

빠른 추가 규칙

- 템플릿은 DB 데이터로 관리하고, 운영 중에는 AI를 호출하지 않는다. 비용이 없고 즉시 동작한다.
- 초기 템플릿 50~100개는 개발 시점에 AI로 만든 뒤 검토해서 넣는다.
- 템플릿을 추가할 때 앱을 다시 배포하지 않는다. (가구 카탈로그와 같은 방식)
- 칩 정렬: 최근에 사용한 키워드 → 진행 중 목표 유형에 맞는 템플릿 → 공통 템플릿
- 목표 유형 템플릿(예: 공부 목표의 '강의 1개 듣기')으로 만든 할 일은 해당 목표에 연결되어 건물 공사에 반영된다.
- 크레딧은 일반 할 일과 같은 규칙을 따른다.

템플릿 예시 (러프안)

| 키워드 | 단위와 수량 선택지 | 목표 유형 |
| --- | --- | --- |
| 독서 | 분 10/20/30, 쪽 10/20/50 | 공통 |
| 운동 | 분 10/20/30, 회 1/3/5 | 공통 |
| 청소 | 분 10/20/30 | 공통 |
| 걷기 | 분 15/30/60 | 운동, 건강 |
| 강의 듣기 | 개 1/2/3 | 공부, 자격증 |
| 문제 풀기 | 개 10/20/50 | 공부, 자격증 |
| 가계부 정리 | 분 10/20 | 저축, 재테크 |

DB 템플릿 방식의 한계와 대응

| 한계 | 대응 |
| --- | --- |
| 장기 목표용 할 일은 사람마다 달라 템플릿으로 일반화하기 어렵다 | 장기 목표 할 일은 AI 분해와 '목표에서 가져오기'가 맡는다. 빠른 추가는 루틴형 할 일에 집중한다 |
| 키워드마다 단위가 다르다 | 템플릿마다 단위와 수량 선택지를 따로 저장한다 |
| 개인화가 약하다 | 사용자가 최근에 쓴 키워드를 앞에 보여주고, 목표 유형에 맞는 템플릿을 우선한다 |
| 칩으로 일반 할 일 5개를 쉽게 만들어 일일 보너스를 받을 수 있다 | 자기 신고 구조라 막지 않는다. 빠른 추가로 만든 할 일 비율을 기록해 확인한다 |

## 10 상태와 처리 규칙

| 상황 | 규칙 |
| --- | --- |
| 할 일 상태 | 할 예정, 완료 |
| 미완료 | 별도 실패 상태 없음. 자동 완료, 자동 실패, 다음 날 자동 배정 모두 하지 않음 |
| 날짜 변경 | 같은 할 일의 날짜를 바꾸고 이전 날짜에서 옮긴 기록 유지 |
| 할 일 쪼개기 | 원래 할 일은 분할 기록으로 남기고 집계와 크레딧 대상에서 제외 |
| 완료 취소 | 당일만 허용. 크레딧과 건물 공사 진행을 회수 |
| 크레딧 회수 시 잔액 부족 | 잔액이 마이너스가 되는 것을 허용하고 이후 지급에서 채움 |
| 중복 완료 요청 | 여러 기기에서 같은 요청이 와도 완료 기록과 크레딧은 한 번만 반영 |
| 목표 보관 | 건물 공사 중지. 건물은 유지 |
| 목표 완료 | 건물 완성. 남은 할 일 정리 방법은 사용자가 선택 |
| AI 분해 실패 | 오류를 안내하고 직접 입력으로 전환 |
| 저장 실패 | 완료나 지급을 확정하지 않고 오류와 재시도 제공 |

## 11 진행 현황과 검증

### 11.1 실행률 계산

- 계획 대비 실행률은 날짜별 수행 약속 중 그날 완료한 비율이다.
- 다른 날로 옮긴 일은 원래 날짜에 '재계획'으로 남는다. 옮긴 날짜에서 완료해도 원래 날짜의 실행률은 바뀌지 않는다.
- 수행 대상이 0개인 날은 100퍼센트로 표시하지 않는다.

### 11.2 검증 방법

- 1차 검증은 본인이 안드로이드 폰에 PWA를 설치해 직접 사용하는 것이다. 7.1의 단계마다 사용해본다.
- 그만 쓰고 싶어지는 순간과 이유를 기록한다.
- 크레딧 수급과 집 업그레이드 속도를 확인하고 러프안 수치를 조정한다.
- AI가 만든 할 일 초안 중 실제로 고른 비율을 확인한다.

| 확인할 지표 | 의미 |
| --- | --- |
| 실행한 날 수 | 주당 할 일을 하나 이상 완료한 날 |
| 미완료 후 복귀 | 쉬었다가 다시 실행하기까지 걸린 기간 |
| 핵심 할 일 실행률 | 핵심 할 일 중 그날 완료한 비율 |
| AI 초안 채택률 | AI가 제안한 할 일 중 사용자가 고른 비율 |
| 가구 구매 간격 | 가구를 사는 주기가 러프안(2~5일)과 맞는지 |
| 빠른 추가 사용 비율 | 생성된 할 일 중 빠른 추가로 만든 비율과, 그중 완료한 비율 |

AI 초안을 모두 해제된 상태로 보여주므로, 채택률은 사용자가 직접 고른 결과로 해석할 수 있다. '모두 선택' 버튼 사용 빈도도 함께 기록하면 초안 품질을 판단하는 데 도움이 된다.

### 15.4 LLM

- 1차 후보: gpt-6-luna (100만 토큰당 입력 0.10달러, 출력 0.50달러)
- 비교 후보: Claude Haiku 5.5 (프롬프트 10만 토큰 이하 기준 같은 가격)
- 비용 추정: 목표 분해 1회에 입력 약 1,000토큰, 출력 약 800토큰이면 1회 약 0.0005달러다. 1,000회 호출해도 약 0.5달러이므로 가격 차이보다 품질로 고른다.
- 결정 방법: 샘플 목표 10개를 두 모델에 같은 프롬프트로 넣고 한국어 품질, 할 일 크기의 적절성, 응답 형식 준수, 응답 속도를 비교한다.
- Spring AI의 공통 인터페이스로 호출해 모델 교체가 설정 변경으로 끝나게 한다.

### 15.8 디자인 진행 방식과 스킬

- 화면 흐름, 화면 명세, 준비 문서는 Claude와 대화하며 만들었다.
- 와이어프레임과 화면 구현은 Claude Code에서 Impeccable로 진행한다. (확정)
- Impeccable은 앱 화면을 코드로 바로 만든다. 그래서 와이어프레임 전에 `chagok-web` 프로젝트 초기 세팅이 먼저 필요하다.

| 스킬 | 상태 | 용도 | 비고 |
| --- | --- | --- | --- |
| Impeccable | 사용 (확정) | 앱 화면 설계와 구현, 빈 상태·오류 상태 보강, 디자인 검사 | 프로젝트 세팅 후 설치. 익명 사용 통계는 끌 수 있음. 자동 실행 훅을 설치 전에 확인 |
| UI UX Pro Max | 보류 | 색, 폰트 같은 디자인 토큰 생성 | 색과 폰트를 정하는 단계에서 필요하면 검토. Python 3 필요 |
| Taste Skill, Hallmark | 보류 | 서비스 소개 페이지, 포트폴리오 사이트 | 앱 화면용으로는 쓰지 않음 |

- 여러 스킬을 동시에 설치하면 디자인 규칙이 충돌할 수 있으므로 앱 화면에는 Impeccable 하나만 쓴다.
- 외부 스킬은 설치 전에 SKILL.md와 훅 설정을 확인한다.

다음 작업은 `chagok-web` 프로젝트를 초기 세팅하고 Impeccable을 설치한 뒤, 핵심 화면(오늘, AI 분해의 초안 선택, 집 내부)의 와이어프레임을 만드는 것이다. 와이어프레임이 나오면 가짜 데이터 구조를 기준으로 API 명세를, 12장을 바탕으로 DB 설계를 작성한다.
